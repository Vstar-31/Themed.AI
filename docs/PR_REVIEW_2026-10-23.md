## Finding and fix

The host persisted free-position coordinates using its construction-time DPI, but
responsive layout multiplied them by the current monitor DPI even when the effective
anchor edge was `None`. A drag between monitors with different scaling could
therefore jump again on the next refresh. Responsive layout now uses the same saved
coordinate scale as `ApplyPosition` and `PositionChanged` for an unpinned edge;
pinned edges retain the current monitor scale used by the anchor resolver.

For example, a physical X of 2400 saved at construction scale 1.5 is X=1600. At
current scale 1.0, the previous responsive path moved to physical X=1600; the corrected
path retains X=2400. The reverse scaling direction is handled by the same rule.
This arithmetic was reviewed in source; mixed-DPI dragging has not been reproduced
on a live multi-monitor desktop. Broader monitor topology and restart behavior
remain part of the manual validation checklist.
